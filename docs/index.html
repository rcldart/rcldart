Apps — same architecture, one per transport

  
Frontends over the core

  
Each is a Foxglove-style Subscribe + Publish frontend on a different transport layer — proof the core swaps cleanly.

  

    

      
CycloneDDS · direct

      
flutglove_dds

      
Discovers the live graph over DDS and decodes every type with a bundled schema registry. No bridge, no WebSocket.

      
layer dds_direct + ros2_cdr  ·  verified live /clock, /chatter round-trip

    

    

      
Zenoh

      
flutglove_zenoh

      
Reaches the graph through a Zenoh router — a single outbound TCP that crosses NAT. Subscribe & publish by topic + type.

      
layer zenoh_ros2 + ros2_cdr  ·  needs zenoh-bridge-ros2dds

    

    

      
Foxglove · WebSocket

      
flutglove_foxglove

      
Connects to foxglove_bridge; discovery and schemas come from the bridge. Publishes via clientPublish.

      
layer foxglove_ws + ros2_cdr  ·  verified 206 topics discovered

    

  

  

    flutglove the full configurable-panel viewer supports all four transports (rcl · CycloneDDS · Zenoh · Foxglove) behind one connection dialog.
